# UI architecture

## Responsibility and boundaries

The UI uses React, TypeScript and Vite with native map/replay components. Deployed builds use same-origin broker APIs and anonymous HttpOnly sessions. Browser state stores view references, never credentials or authoritative evidence. The numbered steps 1 · Investigate, 2 · Evacuation & Crew Access (Guided/Research) and 3 · Response Tracker share navigation, headings, cards, color tokens and state language.

| Path under `ui/src/` | Responsibility |
|---|---|
| `features/layout/` | Page shell, navigation and view persistence |
| `features/layout/components/WorkspaceMap.tsx` | Shared Investigation/Response map, overlays and undocking |
| `features/evacuation/` | Radio/preset preparation, reviewable drafts, simulation conversation and shared replay/evidence views |
| `features/traffic-lab/` | Free-form research scenarios and job selection |
| `features/chat/` | Investigation conversation, citations and answer metadata |
| `features/map/` | ArcGIS map container, basemap note and legends |
| `features/weather/` | Current-weather and forecast sections |
| `features/camera/` | Camera modal, image viewer and sensor panel, read through the broker's camera routes |
| `features/reports/` | Response dashboard, the standalone firetruck exercise entry opened from 3 · Response Tracker, and the owned suppression report workflow (`ResponseRegistryContext`) |
| `features/firetruck/` | Firetruck service client, truck card, map overlay and display helpers |
| `features/radio-monitor/` | Radio Investigation's broker stream hooks and the Investigation detail panel's voice-draft audio section |
| `shared/services/workspaceAccess.ts` | Session initialization, broker headers and error checks; `brokerJson`, the one bounded JSON call (timeout and caller signal) behind the evacuation, Traffic Lab, firetruck and camera requests |
| `shared/services/AgentService.ts`, `AgentEventStream.ts` | Investigation requests and strict AG-UI completion |

| `ui/src/schemas/generated/api-types.ts` (git-ignored) | Generated universal-response schema types |

Traffic Lab access comes from `/simulation-api/v1/workspace-config`; the public build enables it for anonymous visitors. It does not depend on sign-in. Radio Investigation uses preserved recordings and shared server-side geocoding. Presets name historical locations but run current inputs. The standalone firetruck exercise uses the separate synthetic firetruck model.

## Extension rules

Features import each other's modules by direct path (`@/features/<feature>/components/...`); only a few, such as weather, also have an `index.ts`. The evacuation capability's `domain.ts` (pure helpers and types) and `presentation.ts` (components) are the interface Traffic Lab uses for the shared map, comparison and evidence code. Keep Traffic Lab hooks independent of component imports.

Generate contracts before changing callers. Keep result metrics, provenance and units typed at the artifact boundary; avoid `any` and fallback fields that silently convert unavailable evidence into a value. Use deterministic metric helpers and preserve source timestamps, unresolved demand and nonarrivals. View changes, expansion and reload must not submit a job.

A final response requires a validated state snapshot and a successful terminal event. Investigation and simulation use the shared AG-UI reader and broker transport. Simulation checks response context. Traffic Lab exposes a retryable failed initialization state, displays failures from saved history, and opens owned `?traffic_run=` links in a fresh tab. Artifact loaders validate supported version 3/4 envelopes and replay geometry once; deterministic evidence helpers still determine metric availability.

The UI reaches the agent, radio, firetruck and camera services only through the same-origin broker; none of them has a URL or key in a Vite variable. Vite embeds every `VITE_*` value in JavaScript, so none may hold a credential. The publisher sets the build flags itself, blanks every other `VITE_*` name it finds and checks the built assets. The camera calls `/simulation-api/v1/camera/latest` and `/images/{id}`.

## Incident workflow and map

After an explicit radio/reference-place action verifies the location, a saved, read-only investigation collects nearby reported fires, current weather, forecast and official guidance in parallel with road preparation. The draft still requires review and explicit run submission. Guided uses one context panel beside the map: Scenario, Conditions and Ask agent. Radio playback stays mounted above the changing context. The wider area below the map contains response plans, agent activity and simulation detail views, preserving initial and updated plans without forcing long content above the map. The updated plan uses complete server-derived resident/crew/source/assumption evidence for that owned run and its frozen input identity.

The browser polls running investigation receipts every two seconds, with thirty-second reads after completion or when no task exists; explicit start/cancel immediately refreshes. Navigation/reload reads saved work without invoking models. Completed runs started in the open Guided workspace request an updated plan; reopening a run without one offers an explicit build action. Closing the browser does not cancel an already-started investigation. Saved investigations have a 420-second receipt/publication deadline covering source tools and final response formatting. Every Runtime caller forwards its remaining deadline to the transport, including heartbeat-only and silent streams. API process loss produces an interrupted receipt; retry is explicit, not queue-based automatic recovery. One initial and one simulation investigation per visitor may run at once, additionally bounded by `capacity.investigations_per_api_process`. Cancellation fences publication immediately and releases actual execution capacity when the returning call stops.

Guidance guardrail intervention, missing validated output and unavailable retrieval remain explicit failures. The supervisor cannot replace them with an uncited plan. Saved investigation failures retain independently retrieved map/forecast evidence where supplied; retry affects that step and preserves road preparation and completed simulation work.

Detection binds successful provider map/forecast receipts outside model formatting. Scenario-point weather and nearby-fire observations survive either tool completion order; final supervisor formatting cannot replace their measurements or coordinates. Successful provider receipts are published as in-progress snapshots and saved before guidance finishes, so the map can show observations while the plan is running. Only a successful terminal event and validated citations complete a plan. The public supervisor emits a typed completion status; the Runtime attaches location, map, forecast and citations from receipts rather than asking the model to reproduce their JSON.

Public assessments render up to five guidance sections of at most 500 characters, each citing one to three retrieved source passages (a passage is a source sentence of 30–350 characters), with deterministic simulation facts when available ([prompts and evidence grounding](02-multi-agent-orchestration.md#prompts-and-evidence-grounding)). The supervisor's internal completion is a fixed status rather than another generated assessment. Measurements, forecast periods and source citations stay in their dedicated panels, not in Markdown tables. Activity labels describe the action instead of exposing structured-output class names. Any arrived tool result reads “Response received” in both the live and saved views. The label means only that a tool returned data; it certifies nothing about source accuracy, plan safety or simulation validity. Unfinished execution and errors retain separate states. Where the supervisor runs, in the Investigation chat (live) and the incident Agent activity tab (saved), activity nests each specialist call under “Supervisor: received the request” and ends with one synthesis row; rows come only from `RUN_STARTED`, the supervisor's registered specialist calls, its own completion call and the run outcome or saved task status. A supervisor that answers directly shows no delegation rows, and failed, cancelled and interrupted runs read “Supervisor: answer not completed”, never “Completed”, which reflects only the successful terminal event and, like the other labels, certifies nothing about source accuracy or plan safety. Simulation and response-report turns go straight to their specialists and never show a supervisor, and activity that cannot be attributed to it keeps the flat list. Paired crew timing tradeoffs and excluded nonarrivals remain part of the assessment when supplied.

Response plans use one column. Before simulation, the initial assessment is visible with a concise next action. Once the simulation assessment starts, it leads with new deterministic measurements; the initial assessment and full saved guidance are folded. Each plan's Sources disclosure is closed by default, as is each article; title and publisher remain scannable, with the complete retained excerpt, source date, collection review date and allowlisted link inside. Plan text and citation styling follow the enclosing workspace's colors.

`MissionFindings` reuses validated mission metrics and paired crew timing for both Guided and Research Overview and the saved simulation assessment. An assessment's highlights require matching run ID, input bundle ID and SHA256 against the loaded result. Missing or mismatched identity leaves the full saved text inspectable but suppresses highlights. Figures are full-horizon policy differences against baseline, not a generated text diff against the initial plan. Initial investigations contain no simulated outcomes. Resident exits, unresolved demand, assumed exposure, staged crews, paired timing and excluded nonarrivals remain separate; no overall winner is invented. Finding actions select the policy and relevant view, pausing at its peak congestion or the final horizon.

Overview emphasizes outcomes and tradeoffs, with detailed comparisons, replay explanations and exports folded. Bottlenecks shows slowdown, pre-entry waiting, closures and congestion comparisons. Fire crews shows recorded positions and phase, planned origins/routes, staging/return events and crew-only comparisons; Guided's full-run timing table is folded separately from the current replay table. Data & evidence owns provider readings, source refresh, provenance and assumptions. The map/replay controls remain shared.

Both map implementations preserve their capabilities: ArcGIS retains the camera popup action (offered only while the workspace reports `camera_configured`), vegetation, demographics and firetruck overlays; the native SUMO map retains roads, traffic, replay and crew trails. A shared observation projection presents fire/weather measurements and source details. Coordinates must be finite and valid. Missing area, containment, weather and observation time stay unavailable. Weather with no wind measurement still has a marker. Selecting an observation card or F/W marker selects the same source record. Fire and its requested point weather stay together; scenario-point weather remains separately named. Forecasts identify their own source location and regroup source timestamps into Pacific calendar days for the supported California scenarios; generic forecast displays use explicitly labeled UTC. The shared unit formatter handles current and forecast measurements. The default map stays on the study area; “Show nearby fires & weather” explicitly fits the broader observations and scenario point.

The Investigation/Response basemap is OpenStreetMap. Map views are destroyed on unmount to release WebGL resources.

Undocking fills the viewport without remounting the map or resetting policy, replay or run. The click also requests native browser fullscreen, hiding browser chrome where supported; denied/unsupported requests retain viewport presentation. Restore/Escape exits fullscreen and returns focus to the trigger. The standalone exercise remains open when Escape restores its map. Investigation, Guided, Research, the stage-3 replay and the standalone exercise use the same fullscreen hook. The map stays in the same page and keeps its replay controls; Research also keeps policy selection available inside fullscreen. Guided provides radio play/pause inside fullscreen without creating a second audio player. Long recording keys are inspectable under source details and cannot expand the context grid. Crew identity and map action have separate cells; a saved planned origin is labeled as such, while Locate uses the selected frame’s recorded position.

### Numbered workflow and Response Tracker

- **Navigation.** The header is `<nav aria-label="Incident workflow">` with an ordered list of 1 · Investigate, 2 · Evacuation & Crew Access and 3 · Response Tracker. The current step carries `aria-current="step"`, and selecting it does nothing. `viewPersistence.ts` remembers stages 2 and 3 for the tab; choosing Investigation clears it. Builds without simulations show steps 1 and 3, and step 3 explains that there is no run to replay.
- **Selected scenario strip.** Stage 2 publishes `{incidentId, runId, policyId, runStatus}` through `ResponseRegistryContext`, and `ScenarioStrip` shows incident · coordinates · run · policy · status as plain text. The strip is display only: it is never sent in a request, and a reload restores it from the owned session. It shows no observation time, because `KnownFire.lastSeen` is client time.
- **Stage 3 replay.** Stage 3 is the kept-mounted Guided workspace in its `response` stage: the same run, policy, replay clock and `SimulationMap`, without drafts, comparisons or other stage-2 panels. `ResponseTracker.tsx` holds stage 3's own parts (the read-only policy line, crew view, no-replay message and actions), which `EvacuationWorkspace` places around the shared map and replay. Crew roles are demo labels by position in `crew_plan`, taken from `UNIT_TYPES`; they do not change the simulated vehicles, and Rescue and Command show no pumping. Each pumping crew shows one line labeled “Illustrative · not simulated”: 450 gpm (`ILLUSTRATIVE_PUMP_GPM`) over recorded `staging_stop` frames at or before the shown sample, capped at `crew_plan[].service_seconds`. These numbers are never sent to agents or saved.
- **Review response findings.** The button asks the run's `crew_details` suggested question through the usual `/agent/turns` turn with the replayed `policy_id`. Its activity is a flat list titled “Agent activity · sent directly to the Simulation agent”, built from the broker's `simulation_activity` notices, which carry tool names and call IDs only. The live review, with its activity and status, shows only while the policy it was asked under is replayed. Otherwise the latest saved answer to the same question about the run stands in only when it cites at least one policy-bearing fact and every such fact names the replayed policy; an answer citing several policies, as an evidence call without `policy_ids` returns, stands in under none. Saved turns from `/sessions/{id}/turns` do not record the policy they were asked under, so a stand-in rests on its cited facts alone: an answer whose facts all name one policy stands in under that policy, and after a reload an answer citing several stays hidden until the review is asked again.
- **Simulate this search area.** Stage 1 offers the selected answer's place name, kept only when it is text. One click starts one new `radio` session in stage 2 with the place as `reported_address`, so server geocoding, California bounds and the daily limits apply, and no coordinates are sent. A click while another start or turn is busy waits for it, then starts once. The search area, like an address typed in stage 2, replaces an earlier radio report in the context panel; the radio recording stays. “Verified search area” is UI state; after a reload stage 2 shows “Verified scenario point”.
- **Maps.** `MapContainer` memoizes its center from latitude, longitude and name, so unchanged telemetry neither reloads nor re-fits the map, and a fit requested during another fit runs when that one ends. The exercise popup follows the selected unit ID through current positions. When the units legend is present it sits below the undock control and the risk legend moves to the bottom right. The units legend shows only on a map with units and starts collapsed to one “Fire response units” toggle, the shared `Accordion` button.
- **Standalone exercise.** The “Standalone firetruck exercise” button in stage 3 opens the separate synthetic exercise as a sub-view, with `aria-current` still on step 3. “Return to Response Tracker”, or Escape while its map is docked, closes it and returns focus to the button. It is not linked to the selected run or policy. Leaving stage 3 stops an active run with its one stop request, closes its stream and clears its units, which only the exercise map shows; the stopped run keeps its report, reopening the exercise reads its final status once, and a new run needs an explicit Dispatch.

## Agentic UI approach

The workspace follows the stable incident-workspace approach of D49 in the [decision log](decisions.md): the map and evidence stay put while agents work, activity shows the called tool, its execution and returned-result state and duration, and failure, retry, cancel and the next action appear where the work happened. Private reasoning, invented percentages and cosmetic “agent thinking” are never shown as evidence, and reported, prerecorded, assumed and simulated information stay distinguishable where they are used. Desktop places the context panel beside the map; narrow layouts put the map first with a horizontally scrollable status rail. Browser checks verify function, not calibrated trust or operator readiness; small screens and long simulation pages still need presenter testing.

## Verification

ArcGIS map cleanup waits for view readiness and all pending layer-view promises before destroying the view. Browser acceptance delays real layer modules while repeatedly switching Investigation and the standalone exercise to exercise the asynchronous teardown path. Every workspace map also exercises native fullscreen and Escape restoration; the simulation retains its replay time and selected policy.

`scripts/check_quality.py all` runs the UI suites, TypeScript and lint with zero allowed warnings, alongside backend/infrastructure checks. Existing browser acceptance checks cover restoration, ownership, prepared-network review, map/replay and explicit submission. The same harness exercises distinct per-location weather, missing area/containment, received-result labels, Pacific date regrouping, keyboard disclosure, long recording keys, audio element continuity and layout at 1366, 1024, 820 and 683 pixels. Computed normal-text contrast checks require at least 4.5:1 for forecasts, plans, source articles and simulation findings. Plan checks cover folded defaults, complete long excerpts, matching input identity, mismatch suppression and peak-congestion navigation. Tab checks distinguish resident, congestion and crew content. Crew checks distinguish planned origins from actual replay positions. No separate screenshot test runner or one-off Markdown report was added.
